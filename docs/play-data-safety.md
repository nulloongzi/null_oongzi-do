# Play 데이터 보안 설문 — 제출 완료 (2026-08-06)

> **콘솔에 실제로 입력·제출된 값의 근거 문서.** 설문은 앱의 실제 동작에 대한 *사실 선언*이라,
> 코드가 바뀌면 이 문서와 콘솔을 함께 고쳐야 한다. 근거는 전부 코드·`privacy.html`에서 확인한 것.
>
> 2026-08-06 이 내용으로 저장 → 검토 제출 완료.

## 왜 고쳐야 하나

2026-08-06 기준 콘솔 선언은 **"앱에서 데이터를 수집 또는 공유하지 않습니다" + "데이터가 암호화되지 않음"** 두 줄이다.
**둘 다 사실과 다르다.**

- 앱은 소셜/이메일 로그인으로 **계정을 만들고**(`js/auth.js`, `lib/services/social_auth_service.dart`),
  Firestore `users`·`clubs`·`pickup_games`에 쓰고, Storage에 인증 사진을 올린다.
- Firebase는 전 구간 HTTPS/TLS다 → "암호화되지 않음"은 틀렸다.
- 무엇보다 **같이 제출한 `privacy.html`이 수집 항목을 명시**하고 있어 둘이 정면으로 모순된다.
  구글은 데이터 보안 선언과 개인정보처리방침을 대조 검사하고, 부정확한 선언은 게시 중단 사유다.

또한 "수집 없음"으로 두면 **계정 삭제 요청 URL 입력란 자체가 열리지 않아** `data-deletion.html`을 등록할 수 없다.

## 1단계 — 개요

| 질문 | 답 |
|---|---|
| 앱에서 필수 사용자 데이터 유형을 수집하거나 공유하나요? | **예** |
| 앱에서 사용자가 계정을 만들 수 있나요? | **예** |
| 계정 생성 방법 | **사용자 이름 및 비밀번호** + **OAuth** |

**계정 생성 방법 근거**: 이메일+비밀번호는 `createUserWithEmailAndPassword`(`js/auth.js:63`),
OAuth는 Google `signInWithPopup(GoogleAuthProvider)`와 카카오·네이버 `oauth2.0/authorize`
(`js/social-auth.js`). **Facebook 로그인은 없다** — `kFacebookAppId`(앱 `story_share.dart`)는
인스타 스토리 공유 딥링크용 앱 ID일 뿐 로그인 제공자가 아니다.

## 2단계 — 수집하는 데이터 유형

| Play 카테고리 | 세부 유형 | 수집 | 공유 | 필수/선택 | 근거 |
|---|---|---|---|---|---|
| 개인 정보 | 이름 | ✅ | ❌ | 선택 | 소셜 로그인 제공 이름 (`privacy.html` §1 계정) |
| 개인 정보 | 이메일 주소 | ✅ | ❌ | 선택 | Google·이메일 로그인 |
| 개인 정보 | 사용자 ID | ✅ | ❌ | 선택 | Firebase `uid`, `kakao:{id}`/`naver:{id}` 소셜 회원번호 |
| 사진 및 동영상 | 사진 | ✅ | ❌ | 선택 | 팀 인증 사진 Storage 업로드 (`js/registration.js`) |
| 앱 활동 | 앱 상호작용 | ✅ | ❌ | 필수 | Firebase Analytics `logEvent` (`js/firebase-init.js:57`, 앱 `firebase_analytics`) |
| 앱 활동 | 기타 사용자 생성 콘텐츠 | ✅ | ❌ | 선택 | 닉네임·도시락(북마크)·동호회/픽업 등록 내용 |
| 기기 또는 기타 ID | 기기 또는 기타 ID | ✅ | ❌ | 필수 | Firebase Analytics 앱 인스턴스 ID |

**"선택"으로 두는 근거**: 로그인 없이도 지도 조회·검색·픽업 등록(익명)이 되므로, 계정 관련 항목은
사용자가 로그인을 선택할 때만 수집된다(`privacy.html` §1 하단). Analytics는 이용 중 자동이라 필수.

**"공유 = 아니요"인 이유**: Firebase(Google)는 처리위탁(service provider)이고, 카카오·네이버는
사용자가 직접 개시한 로그인 연동이다. Play 기준의 "제3자 공유"에 해당하지 않는다.

### 수집 목적 (제출값)

- 이름·이메일·사용자 ID → **앱 기능**(로그인·본인 콘텐츠 관리 권한) + **계정 관리**
- 사진·기타 사용자 제작 콘텐츠 → **앱 기능**
- 앱 상호작용·기기 또는 기타 ID → **애널리틱스**

**"앱 상호작용 = 애널리틱스만"인 이유**: `logEvent`로 나가는 건 퍼널 이벤트
(`view_club`/`share`/`deep_link_open`/`pickup_contact`)뿐이고 광고·개인화·추천에 쓰지 않는다.
목적을 더 붙이면 오히려 부정확해진다.

> **선택 검토 항목**: 사용자 ID에 **"사기 방지, 보안 및 규정 준수"**를 추가하는 안이 있다.
> `functions/social-auth.js`가 카카오 `app_id`를 대조해 위조 토큰을 막고(주석: "위조 토큰 방지 강화"),
> `privacy.html` §2도 이용 목적으로 "부정 이용 방지"를 명시한다. 방침과 콘솔의 정합성이
> 구글이 대조하는 지점이라 넣어두면 유리하다. 2026-08-06 제출본에는 **미포함**.

### 선언하지 **않는** 것

| 항목 | 이유 |
|---|---|
| 정밀/대략적 위치 | "내 위치"는 기기 내에서만 쓰고 서버에 저장하지 않는다(`privacy.html` §7). 기기를 벗어나지 않으면 Play 기준 "수집"이 아니다. **단, Firebase Analytics가 IP로 대략적 위치를 파생하므로 판단이 필요하다 — 애매하면 "대략적인 위치 / 분석 목적"을 추가 선언하는 쪽이 안전하다.** |
| 앱 정보 및 성능(크래시 로그) | Crashlytics 미사용 (`pubspec.yaml`에 없음) |
| 금융 정보·연락처·메시지·캘린더 | 해당 기능 없음 |

> 동호회 연락처 링크·인스타 링크는 **등록자가 공개 목적으로 입력한 단체 정보**라 개인 연락처 수집이 아니다.
> 인스타 임베드는 공개 게시물의 oEmbed 미리보기일 뿐 계정 접근이 없다(`privacy.html` §4).

## 3단계 — 보안 관행

| 질문 | 답 | 근거 |
|---|---|---|
| 전송 중 데이터가 암호화되나요? | **예** | Firebase Auth/Firestore/Storage·Cloud Functions 전 구간 HTTPS/TLS |
| 사용자가 데이터 삭제를 요청할 수 있나요? | **예** | `privacy.html` §5·§6 |
| **계정 삭제 URL / 데이터 삭제 URL** | 둘 다 `https://do.nulloongzi.com/data-deletion.html` | 새 도메인에서 서빙 확인 완료 |
| 계정 삭제 없이 데이터만 삭제 요청 가능? | **예** | `data-deletion.html`에 "계정을 유지하면서 데이터만 삭제하기" 절로 명시 |
| 독립적인 보안 검토를 거쳤나요? | 아니요 | 해당 없음 (선택 항목) |

> `data-deletion.html`은 이 선언에 맞춰 2026-08-06에 보강했다: 계정 유지 + 데이터만 삭제 경로 추가,
> 그리고 **없는 기능이던 "Meta(Facebook) 로그인" 문구를 제거하고 실제 수단(Google·이메일·카카오·네이버)으로 정정.**
> 심사자가 URL을 열어 대조하는 페이지라 선언과 어긋나면 안 된다.
