# 웹↔앱 시각 패리티 — 반기 검수

> 기능이 같은지는 앱 저장소 `docs/feature-parity.md`, **보이는 게 같은지는 이 문서**.
> 규칙의 원본은 `docs/design-system.md`. 2026-09 에 웹·앱을 한 번 통일했고(시트 모서리·그림자·핸들·FAB·탭·로고),
> 그 상태가 다시 어긋나지 않게 하려는 점검이다. Todoist 처럼 네이티브 앱을 따로 굴리는 팀도
> "일관성은 저절로 유지되지 않는다 — 정기 검수를 둔다"는 결론에 닿았다.

## 1. 언제

- **1월·7월 첫 주.** `.github/workflows/parity-audit.yml` 이 1일에 아래 체크리스트로 이슈를 연다.
  Actions 탭에서 `Parity audit` → Run workflow 로 아무 때나 열 수도 있다.
- 큰 화면(시트·카드·FAB 같은 공용 부품)을 한쪽에서 바꾼 뒤.

## 2. 자동으로 보는 것 — 손으로 안 봐도 된다

| 무엇 | 어디서 | 실패하면 |
|---|---|---|
| 토큰 숫자(색·그림자·모서리)가 웹 JSON 과 같다 | 웹 `tests/design-tokens.test.js` · 앱 `.github/workflows/design-tokens.yml`(주 1회 포함) | `npm run tokens` (design-system.md §0) |
| 검정 그림자·검정 딤 없음, Pretendard 버전 하나, PWA 아이콘이 브랜드 로고, FAB·시트 모서리가 토큰 | 웹 `tests/design-rules.test.js` · 앱 `test/design_rules_test.dart` | 메시지가 가리키는 줄을 고친다 |
| 공유 카드 배치 불변식(QR 을 덮지 않음 등) | 웹 `tests/my-card.test.js` · 앱 `test/my_card_render_test.dart` | — |

그래서 반기 검수는 **사람 눈이 필요한 것**만 본다.

## 4. 의도된 차이 — 고치지 않는다

브랜드(색·글꼴·모양·말투)는 같게, 조작 방식은 플랫폼 관례대로 둔다(design-system.md 머리말).

| 차이 | 웹 | 앱 | 이유 |
|---|---|---|---|
| 지도 엔진 | 카카오맵 | 네이버맵 | 앱 네이티브 SDK 사정. 지도 위에 얹는 것(마커·핀·FAB)만 맞춘다 |
| 필터 시트 방향 | 위에서 내려옴 | 아래에서 올라옴 | 아직 판단 전 — 다음 검수에서 정한다 |
| 릴스 피크를 여는 곳 | 클럽명 라벨 롱프레스(550ms) | 마커 롱프레스 | 누르는 자리만 다르고 동작은 같다 |
