# 카카오 챗봇 스킬·블록 현황

운영자가 카카오톡 챗봇으로 처리하는 관리 작업의 전체 목록이다.
최초 설정(인증 4종)은 `kakao-openbuilder-setup-prompt.md` 에 있고, 그 뒤 늘어난
팀·신고·클레임은 여기에 모은다.

콘솔 주소: https://chatbot.kakao.com
스킬 URL 은 모두 `https://us-central1-nulloongzi-do.cloudfunctions.net/<함수명>` · POST.

## 지금 상태 한눈에

| 발화 | 하는 일 | 블록 ID가 필요한가 | 상태 |
|---|---|---|---|
| `인증관리` | 대기 중 인증 요청 카드 + 승인/거절 | 거절확정 (코드에 박힘) | ✅ 동작 |
| `팀관리` | 팀 목록 + 삭제 | 3개 (코드에 박힘) | ✅ 동작 |
| `신고관리` | 미처리 신고 목록 + 처리완료 | `REPORT_DONE_BLOCK_ID` | ⚠️ **텍스트 모드** |
| `클레임관리` | 소유권 클레임 + 승인/거절 | `CLAIM_APPROVE_BLOCK_ID` · `CLAIM_REJECT_BLOCK_ID` | ⚠️ **텍스트 모드** |

'텍스트 모드'는 고장이 아니다. 블록 ID가 없으면 카드·버튼 대신 글 목록으로
응답하도록 일부러 만들어 뒀다 — 콘솔 설정 전에도 목록은 보여야 하기 때문이다.
대신 처리하려면 목록에 찍힌 `id:` 를 눈으로 보고 발화로 넘겨야 한다.

## 왜 블록 ID가 코드로 돌아와야 하나

버튼을 누르면 "어느 블록으로 보낼지"를 응답에 적어야 한다. 그 블록은 콘솔에서
만들기 전엔 존재하지 않으므로, 순서가 반드시 이렇게 된다:

```
콘솔에서 블록 생성 → 블록 ID 복사 → 설정에 반영 → 재배포 → 버튼 동작
```

인증·팀은 이 ID가 `functions/index.js` 에 상수로 박혀 있고(초기 구현),
신고·클레임은 `functions/.env.nulloongzi-do` 로 뺐다. **새로 설정하는 것은
.env 쪽이라 코드를 건드릴 필요가 없다.**

## 남은 작업 1: 신고관리 버튼 붙이기

### ① 스킬 등록 (2개)

| 스킬명 | 함수 |
|---|---|
| 신고목록조회 | `chatbotReports` |
| 신고처리완료 | `chatbotReportDone` |

등록 후 "스킬 서버 연결 테스트"로 200 OK 확인.

### ② 블록 생성 (2개)

**신고관리**
- 발화: `신고관리`, `신고 관리`, `신고목록`, `신고 목록`
- 봇 응답 → "스킬 데이터 사용" → 스킬: 신고목록조회

**신고처리**
- 버튼 전용(`action: "block"`)이라 발화 패턴은 없어도 된다
- 봇 응답 → "스킬 데이터 사용" → 스킬: 신고처리완료
- 파라미터: `report_id` (string) — 버튼이 `clientExtra` 로 넘기므로 콘솔 설정은
  없어도 되지만, 발화로도 처리하고 싶으면 파라미터로 받도록 열어둔다

### ③ 블록 ID 반영

`신고처리` 블록의 ID를 복사해 `functions/.env.nulloongzi-do` 에:

```
REPORT_DONE_BLOCK_ID=<복사한 블록 ID>
```

(파일에 주석으로 준비돼 있다. `#` 만 떼고 값을 넣으면 된다.)

### ④ 재배포

```
firebase deploy --only functions:chatbotReports,functions:chatbotReportDone --project nulloongzi-do
```

### ⑤ 확인

카카오톡에서 `신고관리` → 카드 목록 + `✅ 처리완료` 버튼이 뜨면 끝.
버튼을 누르면 해당 신고가 `resolved` 로 바뀐다(문서는 지우지 않는다 — "며칠 만에
확인했나"를 나중에 셀 수 있어야 `guidelines.html` 의 영업일 7일 약속을 검증할 수 있다).

## 남은 작업 2: 클레임관리 버튼 붙이기

같은 절차다.

### ① 스킬 등록 (3개)

| 스킬명 | 함수 |
|---|---|
| 클레임목록조회 | `chatbotClaims` |
| 클레임승인 | `chatbotClaimApprove` |
| 클레임거절 | `chatbotClaimReject` |

### ② 블록 생성 (3개)

**클레임관리**
- 발화: `클레임관리`, `클레임 관리`, `소유권관리`
- 스킬: 클레임목록조회

**클레임승인** / **클레임거절**
- 버튼 전용. 스킬만 연결한다
- 파라미터(선택): `claim_id` (string)

### ③ 블록 ID 반영

```
CLAIM_APPROVE_BLOCK_ID=<클레임승인 블록 ID>
CLAIM_REJECT_BLOCK_ID=<클레임거절 블록 ID>
```

`CLAIM_APPROVE_BLOCK_ID` 만 있어도 승인 버튼은 붙는다. 거절 ID가 없으면 승인
버튼만 나온다 — 둘 다 넣는 걸 권한다.

## 알아둘 것

- **응답 5초 제한.** Cloud Functions 콜드스타트가 겹치면 첫 호출이 넘길 수 있다.
  한 번 더 보내면 붙는다.
- **관리자만 쓸 수 있다.** 모든 스킬이 `admin_kakao_ids/{kakao_user_id}` 문서
  존재 여부를 먼저 본다. 남이 발화하면 "권한이 없습니다"로 끝난다.
- **`⚠️ 알림 미발송 N건`이 목록 맨 위에 뜨면** 카카오 토큰이 죽은 것이다.
  신고는 접수됐는데 카톡이 안 갔다는 뜻이라, 토큰부터 살려야 한다
  (2026-09-08 KOE322 장애 참고).
- 카톡 알림의 '자세히 보기'는 해당 팀/픽업으로 바로 간다. 운영자 폰에 앱이
  깔려 있으면 App Links 로 앱이 열린다.
